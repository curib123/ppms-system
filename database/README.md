# PPMS PostgreSQL database

`schema.sql` preserves all 28 application tables, enum types, indexes, checks,
foreign keys, JSONB columns, and quoted mixed-case identifiers. It is generated
from the nine existing PPMS migrations, including the local index correction
recorded in `manifest.json`. The Prisma migration history table is excluded;
this PHP project does not manage the other backend's migration history.

`default_data.sql` contains only data generated by the canonical PPMS seed:

| Table | Rows |
| --- | ---: |
| ProductionArea | 7 |
| PpmForm | 26 |
| AreaPpmAssignment | 26 |
| PpmTemplateVersion | 26 |
| TraceCodeRule | 26 |
| PpmTraceConnection | 56 |
| SystemSetting | 15 |

The five roles remain the existing PostgreSQL `UserRole` enum. No extra role
table, default login, password, production records, sessions, or audit data is
invented. Existing accounts remain in the existing database.

The exact source schema, migrations, and seed inputs are preserved in `source/`.
`manifest.json` records provenance, expected row counts, and SHA-256 hashes.
The checked-in SQL lets PHP install the database without Node.js or Prisma.

## Import into a new database

Use PostgreSQL **17 or newer**. Configure the connection as described in the
root README, create an empty database, then run:

```powershell
php index.php setup install
php index.php setup verify
```

The installer is CLI only, requires an empty `public` schema, validates the SQL
hashes, and imports schema and defaults in one transaction. It refuses to run
over existing PPMS tables. Running `setup verify` checks the exact default data
and counts, so run it on the fresh installation before adding operational data.

For a manual import, use an empty database and one transaction:

```sh
psql -X -v ON_ERROR_STOP=1 --single-transaction -d ppms_ci3 -f database/schema.sql -f database/default_data.sql
```

Do not run these SQL files against the running PPMS database. To use existing
data, configure its database name and credentials and skip installation.
